## 1. 프롬프트별 유효성

| 항목 | 판정 | 요지 |
|---|---|---|
| 공통 프리앰블 | 유효 | `pnpm check`가 루트에 있고 CI와 같은 검사를 돌린다. |
| F1 | 유효, 범위 보완 필요 | 문제와 수정이 맞다. 다만 1단계 분류에서 **볼트 전환**(`VaultSection.tsx:29`)도 "떠나는 경로"인데 지금 `leaving` 없이 호출한다. 함께 고친다. autosave 테스트 18개는 사실이다. |
| F2 | 대체로 유효, 원인 서술 1곳 틀림 | 재큐·상태바 수정은 맞다. "enqueue가 rejection을 삼킨다"는 틀렸다. `preserveAsCopy`가 스스로 catch하므로 reject가 생기지 않는다. 진짜 문제는 `flushPendingSave`가 보존 실패를 호출부에 알릴 방법이 없다는 것이다. |
| F3 | **전제 무효** | `notes_set_pinned`는 화면 어디에서도 호출하지 않는 죽은 명령이다. `notesSetPinned`를 import하는 곳이 없다. 실제 핀 버튼은 문서 텍스트를 바꿔 버전 검사 자동저장을 탄다. 프롬프트가 가리키는 `setPinned`, `open.version`도 존재하지 않는다(실제는 `notesSetPinned`, `savedVersion`). → **명령 삭제**로 대체. |
| F4 | 유효, 정책 보강 권장 | 키 유출 차단 방향은 맞고 `needs_key()`도 이미 있다. 하지만 "키 없는 프로바이더에만 `url:` 허용"이면 Ollama + 임의 https 주소로 **노트 내용**은 여전히 외부로 나간다. 설정에 등록된 baseUrl과 일치할 때만 허용하는 쪽이 더 안전하다. |
| F5a | 유효, 범위 확인 필요 | `TagIndex`는 `notes/`와 `journal/`만 색인한다. `notes_list`의 범위(`notes/` + `rel_dir`)와 맞는지 확인하고, 빈 폴더 표시는 따로 walk한다. |
| F5b | **디스크 캐시 부분은 재고** | 소문자화한 본문을 `.naiteh/`에 저장하면, 볼트 전체의 복사본이 볼트 안에 하나 더 생긴다. 이 복사본은 Drive 폴더 동기화, Git Sync, 새 백업 대상(SFTP·Drive)으로 그대로 퍼진다. 백업 제외 목록에는 `workspace.json`과 `sync-state.json`뿐이다. → **메모리 캐시만** 구현하거나, 디스크 캐시는 앱 설정 폴더에 둔다. 최소 2자 제한은 적절하다. |
| F5c | 유효 | 의존성 추가 시 게시 2주 경과 규칙을 지킨다. 기존 테스트의 role/testid를 유지한다. |

추가로 프롬프트에 없지만 리뷰 검증에서 확인된 것:
- **M7 블록형 `tags:`**: Obsidian식 `tags:\n  - a`가 태그·검색·핀에서 전부 빠진다. F5a와 같은 파서를 건드리므로 함께 처리하면 싸다.

## 2. 구현 계획

### 0단계 — 기준선 정리
- 미커밋 백업 기능(36개 파일)을 먼저 별도 커밋한다. 이후 수정과 섞이지 않게 한다.

### 1단계 — F1 + F2 (데이터 유실, 한 커밋)
1. `authStore.clearSession`과 `VaultSection`의 볼트 전환 flush를 `{ leaving: true }`로 바꾼다. 나머지 호출부(동기화 직전, Ctrl+S, 이름 변경·삭제)는 편집기가 열린 상태라 그대로 둔다.
2. `preserveAsCopy` 실패 시 entry를 `held` 상태로 pending에 되돌리고, 일반 저장과 같은 백오프로 재시도를 예약한다.
3. `flushPendingSave({ leaving: true })`가 `{ preserved: boolean }` 같은 결과를 돌려주게 한다. 창 닫기(`useWorkspaceLifecycle`)는 실패 시 닫지 않고 오류를 보여주며, 노트 전환은 오류를 표시한다.
4. 상태바의 "retrying"은 재시도가 실제로 예약된 경우에만 보인다.
5. 테스트: 로그아웃·볼트 전환 중 held 편집 → `.local-` 사본 저장, 사본 저장 1회 실패 후 재시도 성공, 계속 실패 시 오류 유지와 창 닫기 차단.

### 2단계 — F4 (보안, 한 커밋)
1. 노트·에이전트 front matter의 `url:`은 해당 프로바이더에 **설정된 baseUrl과 정규화 후 일치**할 때만 허용한다. 그 밖에는 `Validation`. 프롬프트의 "키 없는 프로바이더만" 규칙보다 엄격하고, 두 위험(키·내용 유출)을 모두 막는다.
2. `ai_chat_send`와 `ai_infer_title`이 같은 경로를 지나는지 테스트로 고정한다.
3. 위키 domain-model·product-overview에 규칙을 적는다.

### 3단계 — F3 대체: 죽은 명령 제거 (작은 커밋)
- `notes_set_pinned` 명령, 등록, `notesSetPinned` 래퍼, 위키 항목을 삭제한다. 백엔드 테스트는 핀 헬퍼(`set_pinned_in_content`) 수준으로 남긴다.

### 4단계 — F5a + M7 (메타데이터 통일)
1. 프런트매터 파서를 하나로 모은다. Rust의 `parse_header`가 블록형 목록을 읽게 하고, TS `frontMatter.ts`의 태그 읽기·쓰기도 블록형을 지원한다. 쓰기는 원래 형식을 유지한다.
2. `notes_list`가 인덱스 스냅샷에서 메타데이터를 읽는다. 빈 폴더는 디렉터리 walk만 한다.
3. 테스트: 블록형 태그 노트가 태그 패널·검색·핀에 나타나는지, `notes_list` 결과가 기존과 같은지.

### 5단계 — F5b (검색 캐시, 메모리 전용)
- `(path, mtime, size)`를 키로 소문자 본문을 메모리에 캐시하고, 바뀐 파일만 다시 읽는다. 결과는 기존 구현과 동등해야 한다(동등성 테스트). 프론트엔드에 최소 2자 제한을 둔다.

### 6단계 — F5c (트리 가상화)
- 펼쳐진 노드만 평탄화해 윈도잉한다. `FolderRows` 메모, 콜백·`buildTree` 메모. 의존성을 추가하면 2주 경과 버전을 쓴다.

### 커밋 순서와 판정
`백업 기능` → `F1+F2` → `F4` → `F3 대체` → `F5a+M7` → `F5b` → `F5c`. 단계마다 `pnpm check` 통과가 완료 조건이다. architecture.md를 고치는 커밋에만 `[architecture]`를 붙인다.

## 3. 프롬프트 문서 자체의 수정 제안
- F2의 "enqueue가 rejection을 삼킨다" 문장을 "flushPendingSave가 보존 실패를 호출부에 알리지 못한다"로 바꾼다.
- F3을 "죽은 명령 제거"로 교체한다.
- F4의 정책을 "설정된 baseUrl과 일치할 때만 허용"으로 바꾼다.
- F5b의 `.naiteh/` 디스크 캐시를 메모리 캐시(또는 앱 설정 폴더)로 바꾼다.
- F1 1단계에 볼트 전환 호출부(`VaultSection.tsx:29`)를 명시한다.
